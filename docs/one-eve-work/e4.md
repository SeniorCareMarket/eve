# e4 — exact numbers: Clojure tokens on JVM/bb, tagged literals elsewhere

John 2026-11-11 10:20 ET: where a host cannot represent or print an exact
number the way JVM Clojure does, do not necessarily build a full arithmetic
tower. Represent it as a reader-tagged value that round-trips losslessly
and floats around on that host. JVM/bb still read/print native `1N`, `1/3`,
`1.5M`.

## Tags

| typetag | tagged EDN (nbb, basilisp, BEAM) | Clojure token (JVM, bb, and `pr-number` everywhere) |
|---|---|---|
| bigint | `#eve/N "123"` | `123N` |
| ratio | `#eve/ratio "1/3"` | `1/3` |
| BigDecimal | `#eve/M "1.2300"` | `1.2300M` |

The form is a string so a host reader never has to parse lexical `N` / `/` /
`M` tokens (nbb today silently rounds them) and so trailing zeros in a
decimal (`1.2300`) survive.

**Why these names.** They follow the `#inst` / `#uuid` pattern (a namespaced
tag and a string form) used by Clojure and by cohost's ClojureScript EDN
reader (which merges the `inst` and `uuid` tag parsers from
`cljs.reader/*tag-table*`). cohost has no separate float tagged-literal
(IEEE `##NaN` / `##Inf` are already reader tokens); this is the same
shape. The `eve/` namespace is Eve's portable exact-number surface. `N`
and `M` are Clojure's own suffixes. `ratio` is the typetag name — a tag
named `/` would be illegal. Every host also *reads* the tagged forms, so
EDN can move from nbb to the JVM.

`eve.numeric/pr-number` and `eve.numeric/read-number` always use the
Clojure token spelling. That is what eve.db.ds serialize (d1,
`lane-m/eve-db-ds-one-eve-d1` `1d02cecaaa`) should use for `[1 <EDN text>]`
instead of host `pr-str` / `read-string` and the `:serialize/exact-number`
guard.

## Required surface vs optional arithmetic

Required, on JVM, bb, nbb, basilisp (BEAM best-effort):

- typetags and accessors (numerator / denominator / scale / unscaled-value)
- `equiv` / `hasheq` / `exact-compare` matching Clojure 1.12
- lossless print/read of Clojure tokens (`pr-number` / `read-number`) and
  of the tagged forms (`host-pr-number` / registered readers)
- codec 0x16 / 0x17 / 0x18: cljs now *decodes* RATIO and BIGDEC to Eve
  types instead of refusing

Arithmetic (`add` / `sub` / `mul` / `divide` / `quot'` / `rem'` / `mod'`)
is implemented and lightly tested, but optional. cljs.core `+` does not
dispatch on the Eve types; callers who want exact arithmetic on nbb should
use `eve.numeric/add` (etc.).

Tag readers hang off `eve.deftype.registry` as per-type `:type-io`
entries (`:tag`, `:read`, `:print`, `:reader-active?`) — the same shape
e1b uses — via `register-type!` / `data-readers`. There is no parallel
tag registry in `eve.numeric`. `install!` and `host-pr-number` remain
the host printer/reader hook; no per-host `print-method` in user code.
e1's deftype `:print` / `:read` wiring should share this registry.
