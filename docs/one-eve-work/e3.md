## APIs
- `eve.type/token` accepts qualified type symbols, including JVM classes with no var (`(t/token dp/Variable)`). Stable token is `:eve.db.ds.parser/Variable`.
- `eve.type/type-token` obtains that keyword without allocating a dummy instance. `condp =` and `case` dispatch on it.
- `(eve.type/instance? dp/Variable x)` handles qualified type symbols without JVM import or per-target branches. Runtime `instance-of?` accepts tokens, or exact native type values.
- Process-local and slab-backed `eve.deftype` expansions auto-register their native realization. This does not overwrite JVM class mappings with vars: doing so would break constructor/type-hint resolution. The Eve API makes the class/var distinction invisible to callers.
- `eve.protocol/defprotocol` accepts `:extend-via-metadata true`. On Basilisp it preserves singledispatch registration and interface priority, with metadata ahead of external extensions.
- Basilisp's Eve type producer supplies throwing implementations for omitted protocol methods, matching Clojure's partial-implementation model. It does NOT invent application behavior for missing methods.
- `eve.math/sqrt`: native correctly-rounded binary64 sqrt (finite bits/sign of zero tested, NaN semantic/canonical rather than payload identity); negative values become NaN on Python instead of ValueError. This is the only remaining host Math operation in DS src at this base.
- `eve.compare/compare`: category order plus recursive collection comparison; never dispatches host Comparable for mixed types. Clojure scalar/vector order where defined, signed-half UUID order, canonical map/set order. NaN placed last for transitivity. Unknown opaque host objects have only a printed-representation total preorder, not portable identity; implement `IOrderKey` to give them portable ordering.

## Integration cautions
- Replacing `db/value-compare` with Eve compare makes `class-identical?`, `class-name`, `class-compare`, `seq-compare` and `orderable-value?` unnecessary. The `class-identical?` inline conditional at `db.cljc:732` is one additional deletion after verifying no external consumers. Retain `int-compare` because datom entity/tx comparators still use it.
- The new category/structural mixed-type ordering differs from the former host-class/hash ordering. Persisted indexes must be rebuilt/migrated rather than reused under a changed comparator. Re-run the full DataScript suite before integration.
- IEEE sqrt fixtures use existing Eve byte encode/decode, and are independently checked against JVM Math and bb Math. They exposed reader-level issues with decimal edge literals on Basilisp and `-0.0` on SCI. Those readers/towers were NOT changed; sqrt gets bit-exact binary64 inputs through the existing encoding surface.
- Comparison found a separate Basilisp instant bug: naive `#inst` values could not subtract an aware Unix epoch. Python `date-ms` now treats naive instants as UTC; JS `date-ms` was added to match the existing JVM/Python encoding API. This is instant conversion, not a new numeric codec.
- Per ds-lanes' numeric-tower steering: NO exact-number type or codec was added. Numeric pairs delegate to the host's core compare; a future VS numeric tower needs to participate in numeric classification/comparison (or supply IOrderKey). The sqrt surface accepts binary64 inputs, not a new number representation.
