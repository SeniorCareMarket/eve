# e5 — encoded HAMT bulk construction

Base: `13421bebb9a2786cd1827974d27268bd15331242`, the fetched
`origin/lane-m/eve-db-ds-gaps-eve` tip at worker creation. Both remotes are
`johnmn3/atom.broker`; e2/e3 collation was not yet on that remote tip.

## Design

An empty Eve set/map's transient now snapshots each input as its existing
canonical key bytes plus the existing portable Murmur3 hash (and encoded
value bytes for maps). `persistent!` partitions those encoded entries by
portable hash bits and writes each final bitmap/collision node once. No
intermediate slab nodes, byte-array reads for path-copying, or re-encoding
for reclaim walks. Byte equality is still authoritative, with map duplicate
keys retaining the last encoded value. Numeric hash buckets are only a
scratch index, never a replacement host-value hash.

Nonempty transients retain the old incremental path. Observing a pending
transient (`get`, `contains?`, `count`), removing from it, or conjoining a
non-entry to a map flushes the batch and resumes the incremental path. The
input collection remains immutable and its blocks remain owned by it.
Encoding remains eager; no caller-owned mutable input is retained in place
of an encoded snapshot. Temporary encoded entries cost O(input bytes)
until flushing; this is a bulk-build optimization, not an unbounded global
identity cache.

The emitted node layouts, key/value encodings, header flags, and hash
function are unchanged. Slots are emitted in unsigned 0..31 order,
including the bitmap sign-bit slot and the two-bit final level. Existing
readers and persistent operations consume the output without conversion.

## Regression coverage

Added to `eve.collection-hash-test`, already registered in all four host
runners: independently known Murmur3 answers; 1k string-vector keys;
duplicates; observation/flush and removal; nonempty-source immutability;
empty input; actual full-hash collisions (including a duplicate key) and
integer keys meeting at
the final two bits; oversized map payloads (the 16-bit size cache must be
zero rather than truncated); and further writes to the bulk-built result.

Standalone reproducible JVM microbench: `clojure -J-Xmx1g -M
bench/hamt_into.clj` from `eve/`. Seven rounds, median per operation; 50
warmups, 100 builds/round for initial 100-key samples, 3 for 10k, followed
by steady-state 100-key samples (1000 builds/round after 10k priming). Disposal is outside the
timer. The baseline uses pristine set/map files from the base commit on an
override classpath; the same benchmark body is used for both. Also measures
encode-key + portable-hash without any slab/trie work to expose the floor.

## Experiments

A second variant packed each bitmap into one temporary byte array and did a
single region write. It was rejected, not assumed faster: the 10k set case
regressed from 18.768 ms (bulk direct writes) to 52.295 ms, and the map from
24.855 to 55.218 ms. The final code retains the existing slab writers.
These exploratory measurements precede the final steady-state comparison.
No global element memo or host-value hash replacement was added.

### JVM benchmark results (milliseconds/build)

100-key rows below are the steady-state samples after 10k priming. Inputs
are vectors containing one string, `N0` onward; map values are `"value"`.

| Collection / size | Eve before | Eve after | Speedup | Clojure before / after |
| --- | ---: | ---: | ---: | ---: |
| Set / 100 | 1.147610 | 0.189428 | 6.06x | 0.003222 / 0.003517 |
| Set / 10,000 | 115.949884 | 18.738166 | 6.19x | 0.457287 / 0.483850 |
| Map / 100 | 1.165027 | 0.250092 | 4.66x | 0.004865 / 0.005959 |
| Map / 10,000 | 166.196053 | 28.347473 | 5.86x | 0.561346 / 0.638783 |

The **within-3x-Clojure target was not met**: the final 100-key set is
53.9x the warm host set. The unchanged encode+portable-hash loop alone is
0.028437 ms (8.1x that host build), so achieving 3x needs more producer work,
not a host hash substitution. This is a measured CURRENT-codec floor, not
a claim of a fundamental lower bound or that this patch reached the floor.

A separate 100-key phase profile (`bench/hamt_into_phases.clj`) measured:
36 final nodes; encode+hash+entry packaging 0.040597 ms; dedup 0.012272 ms;
preencoded unique-entry trie planning 0.045624 ms; scoped preencoded slab
build 0.151853 ms; complete into 0.192281 ms. The scoped build already
includes dedup/planning: do not add these overlapping numbers. Region
allocation/writes and portable planner allocations still dominate the
remaining gap. No further speculative cache or allocator redesign was
attempted. Raw samples are in the adjacent `e5-bench-*.txt` files.
