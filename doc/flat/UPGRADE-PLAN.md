# Flat upgrade law — implementation plan

Decided Nov 13 2026 (John). This plan captures the requirements
from the flat-in-atom design discussion of Nov 13 and orders the
build. It amends FLAT-IN-ATOM-PLAN.md: where the two disagree,
this document governs.

## The frame

Flat Eve data is **Valhalla-like**: value semantics, no identity.
A flat value is its content — equality is content equality, hash
is content hash, and nothing about a flat value answers "which
one is this" because the question does not apply. Eve-persistent
data is the opposite pole: it carries identity (it lives in
atoms, under roots, held by tallies). The two forms meet at
well-defined borders — freeze, ingestion, read-out — and the
rules below are the border law.

## Governing correction (Nov 13 2026, late — John)

Flat is a **subtree storage form**, not a root property. From a
nesting perspective inside an atom, persistent vs flat has
nothing to do with the root pointer. This section supersedes
the in-atom readings of R2/R7/R10/R14 below.

- **Fixed classes only.** All flat objects live in fixed-size
  classes, NEVER in the variable class 15 (kernel numbering;
  the coalescing class on the legacy seat). This was agreed
  when the flat ladder classes were made: chunks do not go in
  the variable class. A frozen replacement is stored as one or
  more chunks in fixed-size classes, every chunk but the last
  16 KiB. (On the legacy CLJC seat, whose fixed classes top
  out at 1024, a chunk is striped across fixed-class blocks;
  on the ladder seat a chunk is one block. Either way, no
  allocation a freeze makes may land in the variable class.)
- **freeze/thaw are generated methods.** Freezing an object
  inside a persistent object is a replacement like any other
  edit, and freeze/thaw are essentially a new implicit method
  pair on every Eve deftyped object — generated by eve-deftype
  the same way the flat sister is. There is no root adoption,
  no frozen-root object, and no pointer to the atom ever
  leaves the atom (a returned root pointer is an identity
  leak, and its lazy reads are unpinned — the tag-0 defect of
  Nov 13 was exactly that leak biting, not a design fork).
- **Read-out collates.** Reading a value out of the atom
  walks the tree from the read point and naturally collates
  persistent and flat in-atom data into one flat object. The
  walk does not distinguish which subtrees were stored flat.
- **What backs out:** the FrozenValue root object, swap!
  root adoption, the 0x20/0x21 root header kinds and their
  tally root-kind cases, deref returning the internal root
  object, and size-routed chain segments that can land in
  the coalescing class. What survives: the chunk format and
  packer, the chain byte layout, the whole heap side (S1/S2),
  and tally subtree holds.

## Requirements

**R1 — No identity in flat.** Flat values never carry identity:
no reference equality, no identity hash, no pinning semantics of
their own. Any mechanism that needs identity works on the
persistent side.

**R2 — Upgrade embeds by reference (the law).** When an edit
cannot be expressed inside the flat form, the result is a
persistent object that EMBEDS the flat one by reference. The
flat original stays where it was — in an atom, the same slab
blocks under the same tally holders; the edit lives in a
persistent overlay on top. Upgrade costs the edit, never the
value. The full-materialize upgrade built in S2 is superseded.

**R3 — No automatic refreeze.** Nothing refreezes on its own —
not on edit, not on swap, not on any threshold. `refreeze` is an
explicit verb that collapses a composite (base + overlay) back
to pure flat form. Callers choose it (e.g. before shipping, or
when an overlay has grown fat).

**R4 — Chunk-local edits path-copy.** A chain is a persistent
list of chunk links. An edit inside one chunk re-packs only that
link and copies the spine; every other link is shared as-is.
In an atom the shared links are the same slab blocks,
tally-bumped. This holds for delivered handles (heap byte-array
links) and atom-resident chains alike — the ConcatBatch assoc
throw is subsumed by this rule.

**R5 — Shape-breaking edits re-pack one chunk.** An edit that
breaks a chunk's shape plan (a value outgrows its column,
changes type class) re-packs that chunk only; shape is
per-chunk, so re-planning is local. Frozen map roots chain by
entry ranges under the same law (today they pack as one chunk
regardless of size — that ends).

**R6 — Whole-value transforms are packer verbs.** Sort, filter,
`into` and friends are not link mutations; they build a new
flat value through the packer. This is the only "refreeze-like"
operation and it is always explicit.

**R7 — Composites live only inside atoms.** A persistent object
with an embedded flat base is an atom-internal stored form.
Persistent Eve never leaks outside atoms. Reading a composite
OUT of an atom (delivery) yields a regular flat object again:
the read-out collapses base + overlay into flat form. Plain
materialization to host values stays the explicit escape hatch.

**R8 — Host nesting works.** Flat handles nest inside host
Clojure structures in the host heap; navigation (`get-in`,
`nth`, `seq`, …) works there through the handles' protocols.

**R9 — Walkability is the shipping contract for mixed
structures.** Flat objects are walkable: they satisfy the
collection protocols an encoder traverses (count, nth, get,
seq, entries). An encoder that creates its stream by walking
those protocols — Transit and its kin — ingests a flat object
nested inside host data with no flat-specific code: it encodes
the logical content, and the far side receives that content
(plain data, unless it is re-frozen on receipt). No special
mechanism is required; the obligation is on the handles to
keep the walking surface complete. Acceptance: a Transit
round-trip of a host structure nesting flat handles, content-
equal on the far side. Any gap an encoder exposes in a
handle's protocol surface is a handle defect, fixed in the
handle. (Amended Nov 13 2026, John's second thought: "since
flat objects are walkable, maybe transit and the other things
that create their streams will ingest flat eve objects in
nested objects just fine.")

**R10 — Ingestion embeds.** Feeding an atom host data that
contains nested flat handles turns the host parts into
persistent Eve data, with the flat parts embedded by reference
at the positions they occupied in the host structure. The flat
subtrees are NOT materialized and re-serialized on the way in.

**R11 — Read-out symmetry.** A stored mixed value reads back
out whole, as pure flat Eve data again (R7 applied to the whole
tree, embedded parts included).

**R12 — Root recipes.** Each chunk root carries a recipe:
(a) the content digest (already computed as `eve-digest` on the
checked/stream paths) plus a latched hasheq word — hash becomes
a field read, equality becomes a digest comparison with the
walk as fallback; (b) a compiled field plan per shape, built at
open from the chunk's own shape table — field → column +
decoder in a primitive array, so a point read is an arrayref
and one decoder call and no row view is materialized. Recipes
are built at pack time from data already in hand (the only
added work is the digest pass the checked/stream paths already
pay), live in a fixed root slot, and are consulted ONLY by
handle methods — swap/place/deref machinery never reads them,
so the atom's read/write costs do not move.

**R13 — Composite equality is logical.** A composite equals
its materialization, its refrozen form, and any plain value
with the same content (the standing one-equality-domain law).
Composite digest = a defined combine of base digest and
overlay digest, so equality short-circuits the same way flat
equality does under R12.

**R14 — Tallies hold embedded bases.** A stored composite's
overlay blocks serialize normally; the flat base is written as
a reference child — a pointer to the flat root — and the tally
counts the referencing root as a holder. Retiring the composite
frees the overlay and drops the base's holder count; the base
survives exactly while other holders exist. (The canonical
free-space census proof owed from the S2b chain acceptance
folds in here as an acceptance test.)

**R15 — Stream send of a composite emits its flat form.**
The wire bytes for a composite root are identical to the bytes
for its refrozen form. Whether the sender refreezes transiently
or merges base + overlay in the walk is an implementation
choice; the bytes are the contract.

## Mechanics per seat

- **swap! cur:** the swap function receives the stored form
  (a composite stays a composite — protocol-complete, edits
  overlay). No form change is forced by reading inside.
- **deref / delivery:** flat form out (R7/R11). A deref that
  delivers flat was the standing assumption for frozen roots;
  composites follow the same rule.
- **The serializer gains a flat-reference node:** the persistent
  codec writes a tagged reference (flat root pointer) where a
  subtree is an embedded flat value, and the reader resolves it
  to the flat root handle (a FrozenValue) as that subtree's
  value. This node is the R2/R10 mechanism — one seam serving
  upgrade, ingestion, and subtree composition.
- **On the bare heap** there is no Eve-persistent to upgrade
  into: editing a delivered handle is chunk-local (R4/R5) or it
  materializes to host data (the escape hatch). Embed-by-
  reference composites exist at the atom border (R10) and
  inside atoms (R2), not as a heap representation.

## Build order

**S1 — Composite + edit paths, heap side.** A BasedValue type
(base flat handle + persistent overlay) implementing the
collection protocols by delegation: overlay first, base
fall-through; count/seq/hash/equality per R13. FrozenValue and
handle assoc paths that cannot stay chunk-local produce it.
Acceptance: edit a delivered multi-chunk value at a
chunk-crossing path — answer is a BasedValue, base untouched
(same chunk objects), reads/equality/hash match the
materialization; chunk-local edits still answer flat (R4).

**S2 — Root recipes (R12).** Digest + hasheq slot in the chunk
root; digest-first equality; compiled field plans at open.
Acceptance: the heap battery re-run — hash and equality on the
canonical corpora drop from walk-scale (46–184 ms) to
field-read scale; point access drops from 1,274/1,878 ns
toward the low hundreds; pack time grows by no more than the
digest pass; wire bytes for non-recipe readers are unaffected
(the slot is flagged and skippable).

**S3 — The flat subtree form (governing correction).**
Backout first: the FrozenValue root machinery (above) is
removed; the pre-freeze suites return to green. Then:
(a) chunk storage is pinned to fixed classes — the chain's
segment stripe is cut at the seat's fixed-class top, so no
freeze allocation lands in the variable/coalescing class;
(b) the serializer gains the flat subtree node: meeting a
freeze-marked value on the write walk packs it and writes a
tagged node heading its chunk chain; the read walk resolves
the node to the subtree's logical value; the tally's block
scan walks the chain as the node's children, so retire holds
and frees it like any subtree; (c) freeze/thaw ship as
generated methods on eve-deftyped objects (a marker the
serializer honors on write; thaw = read as persistent).
Acceptance: an atom whose root is a persistent map with one
frozen vector subtree — deref equals the plain value; the
frozen subtree's blocks are all in fixed classes (coalescing
usage unchanged by the freeze); editing a sibling key leaves
the subtree's blocks untouched (same indices); replacing the
root and churning returns the domain's free space to the
pre-freeze census (the owed retire proof).

**S4 — Ingestion + read-out collation (R7/R10/R11).** swap!
of host data containing delivered flat handles stores those
subtrees in the flat node form (bytes striped in, not
materialized); the delivery walk collates mixed persistent +
flat trees into one flat object. Acceptance: a host map
nesting a delivered flat value, swapped in and delivered
back, answers a flat object equal to a from-scratch freeze
of the same logical value; plain deref materializes the same
logical value as host data.

**S5 — refreeze verb + stream send (R3/R15).** `refreeze`
collapses a stored composite in place (new pure-flat root);
send-stream over a composite root emits R15 bytes.
Acceptance: a composite refrozen compares equal (and digest-
equal) to its pre-refreeze self and to a fresh freeze; stream
round-trip of a composite lands a value equal to the
materialization on the far side.

## Decision points captured with defaults

- swap! cur delivers the stored form (composite included) —
  default from the no-forced-form-change principle.
- deref delivers flat for based roots, as for frozen roots
  (open question 1 of FLAT-IN-ATOM-PLAN, still John's to flip).
- The recipe slot is an optional flagged root block; readers
  that predate it skip it (FORMAT-V1 addition rules).
