## 7. Security posture statements

At base there was **no SECURITY.md** and no statement of what eve encrypts; `SECURITY.md` (`007d4edc8`) now states
7.1 (`:22-37`), 7.2 (`:39-49`), 7.3 (`:51-62`), 7.4 (`:63-65`) and 7.5 (`:66-69`); 7.6's address was supplied by the operator 2026-11-03
(`:6-10`). The facts [read]:

| Item | Status | Fix |
|---|---|---|
| 7.1 Disk domains | ⚠️ **plaintext by default**. Encryption is opt-in through `eve.keyring/open-encrypted-domain!` (`keyring.cljc:377-400`), a lower-level API than `e/atom`. Its default mode (`:status` 1, "auto") **stores the group key in plaintext in `{base}.keyring` beside the data** (`keyring.cljc:102-125`); modes 2/3 take a user key (3: not stored, fingerprint only). AES-256-CTR under an HKDF-derived per-class key, **no integrity**, keystream reuse when a block is rewritten in place ("CTR confidentiality against a single copy of the files", `keyring.cljc:16-19`); slab headers, bitmaps, overflow descriptors, the root file and the atom table stay plaintext | **S**: done (`007d4edc8`): SECURITY.md states exactly this, and that mode 1 protects nothing against a reader of the directory |
| 7.2 Network atoms | ⚠️ **plaintext unless the config carries `:gak`** (`net/atom.cljc:28`, `net/blobs.cljc:8-27`). With a GAK, a blob's key is derived from its plaintext's hash, so equal plaintexts encrypt equally, and the blob's address is the **plaintext's SHA-256** — the store sees plaintext content hashes (content confirmation is possible) | **S**: done (`007d4edc8`): SECURITY.md states it |
| 7.3 The portable crypto | ⚠️ hand-written SHA-256, SHA-512, AES, XXH3, Ed25519, Poseidon2; **not constant-time, said so** ("not a hardened signer", `net/ed25519.cljc:15-17`); it is the **only** crypto on the browser, jolt, glojure and ValueScript (`hosts.edn`: `:browser` takes `crypto/portable` since `4bcd756cc`); no audit | **S**: done (`007d4edc8`): SECURITY.md lists the hosts whose signing is the portable code (`:59`, the browser included); **L** for an external review |
| 7.4 Entropy | ⚠️ `process/vs`'s `random-bytes` is "clock-seeded, not cryptographically strong" and `crypto/vs`'s refuses (`adapters/README.md`) | **S**: done (`007d4edc8`): SECURITY.md: never mint a group key on ValueScript |
| 7.5 Ed25519 small-order keys | ✅ eve refuses the 8 small-order encodings on every host (`eve.net.ed25519/well-formed?`); ⚠️ the VS kernel's verifier accepts the identity key (network-atoms/ADAPTERS.md §5), so broker and client can disagree | **M** (VS kernel owner): align `ed25519.vs` |
