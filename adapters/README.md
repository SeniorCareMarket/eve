# eve's adapters

eve's shared code (`eve/src`) is written once against eve's host interface
("eve is portable": the shared code names no host). An adapter implements one **feature**
of that interface over one host capability. Adapters are organized by
feature, not by host: every host with the same capability uses the same
adapter, and a host is the list of adapter roots on its classpath —
`eve/hosts.edn`, which `bb.edn`'s tasks and the coop capstone read (and
`deps.edn` repeats for the JVM and ClojureScript).

```
adapters/<feature>/<implementation>/src/   ;; the adapter's namespaces
```

Which features a new language must write, which ship portable and work as they are, and which a host replaces
for speed: [`doc/adopter-tiers.md`](../doc/adopter-tiers.md) (the minimal, inbuilt and
fast sets), and the guides [`doc/adopting-eve-minimal.md`](../doc/adopting-eve-minimal.md) and
[`doc/adopting-eve-fast.md`](../doc/adopting-eve-fast.md).

## Features

One row per interface, then one row per implementation. The **Hosts** column is `hosts.edn`, inverted (checked
2026-10-20): the hosts whose row lists that root. Host names: JVM (`:jvm`), ClojureScript on Node (`:cljs`),
ClojureScript in a browser (`:browser`), babashka (`:bb`), nbb (`:nbb`), ClojureCLR (`:cljr`), basilisp (`:lpy`),
jolt (`:jolt`), clojerl (`:clje`), ValueScript (`:vs`), glojure (`:glj`), cherry (`:cherry`), let-go (`:lg`), ClojureDart (`:cljd`). "ClojureScript's compiler" means the
JVM roots that `:cljs` and `:browser` carry for the compiler's own Clojure (its macros run there).
